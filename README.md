# Threadline — Parallel Document Search

Threadline — пошукова система для текстових документів, реалізована мовою C++. Вона підтримує паралельну побудову інвертованого індексу, пошук за ключовими словами та розширення пошукового запиту за допомогою Ollama.

## Можливості

- Індексація текстових файлів із налаштуванням кількості робочих потоків.
- Інвертований індекс із паралельним доступом.
- Два режими пошуку: `keyword` та `expanded`.
- REST API та WebSocket для передавання етапів пошуку.
- Вебінтерфейс і консольний клієнт.
- Статистика побудови індексу.

## Технології

- C++17
- Docker і Docker Compose
- Ollama
- HTML, CSS, JavaScript
- Python 3 для тестування та вимірювань

## Вимоги для запуску

- Docker із підтримкою Docker Compose.
- Локальний набір англомовних `.txt` документів у папці `data_10000`.
- Модель Ollama, налаштована в конфігурації проєкту.

Набір `data_10000` використовується локально. Під час тестування використано 10 000 документів загальним обсягом приблизно 2,6 ГБ.

## Запуск

У кореневій папці проєкту виконайте:

```bash
docker compose up -d --build
```

Перевірка роботи сервера:

```bash
curl http://localhost:8080/api/health
```

Вебінтерфейс: http://localhost:8080

Перед пошуком потрібно побудувати індекс. Це можна зробити через кнопку налаштувань у вебінтерфейсі або через API:

```bash
curl -X POST http://localhost:8080/api/index \
  -H "Content-Type: application/json" \
  -d '{"threads":12}'
```

Перевірка статистики:

```bash
curl http://localhost:8080/api/stats
```

Після індексації в статистиці має відображатися кількість оброблених документів. Якщо контейнер пошукового сервера перезапускався, індекс в оперативній пам'яті потрібно побудувати знову.

## Пошук

Звичайний пошук:

```bash
curl -X POST http://localhost:8080/api/search \
  -H "Content-Type: application/json" \
  -d '{"query":"space adventure","mode":"keyword"}'
```

Пошук із розширенням запиту через Ollama:

```bash
curl -X POST http://localhost:8080/api/search \
  -H "Content-Type: application/json" \
  -d '{"query":"space adventure","mode":"expanded"}'
```

У вебінтерфейсі можна вибрати режим `Keyword` або `AI expanded`. Для розширеного пошуку потрібна доступна й налаштована модель Ollama.

## API

| Метод | Шлях | Призначення |
| --- | --- | --- |
| GET | `/api/health` | Стан сервера та доступність Ollama |
| POST | `/api/index` | Побудова індексу, параметр `threads` |
| GET | `/api/stats` | Кількість документів, час індексації та потоки |
| POST | `/api/search` | Пошук, параметри `query` і `mode` |
| WebSocket | `/ws/search` | Етапи оброблення пошукового запиту |

WebSocket передає етапи `query_expansion` (для розширеного пошуку), `keyword_search` та `done`.

## Тестування

Після запуску сервера та побудови індексу виконайте:

```bash
python3 tests/test_search.py
```

Скрипт містить 10 функціональних тестів та перевіряє п'ять додаткових пошукових запитів. Для WebSocket-тестів потрібен пакет:

```bash
python3 -m pip install websocket-client
```

Результати пошукових перевірок записуються у `results/search_correctness.csv`.

Для дослідження продуктивності використовувався скрипт `tests/benchmark.py`. Час індексації вимірювався для 1, 2, 4, 8, 12 та 16 потоків; пропускна здатність — для 1, 2, 4, 8, 12, 16 та 32 одночасних клієнтів. Отримані результати наведені в пояснювальній записці.

## Завершення роботи

```bash
docker compose down
```
